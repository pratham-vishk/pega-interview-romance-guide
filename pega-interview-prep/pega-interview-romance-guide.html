Chapter 1: First Impressions — Pega Platform & Architecture

They say you never get a second chance at a first impression. Pega says: build it once on the platform, reuse it everywhere. Kind of like how I can't stop thinking about how prepared you're about to be.

What is Pega?

Pega is a low-code BPM + CRM + Case Management platform built on Java. It uses a rules-driven, model-driven architecture where business logic is externalized into declarative rules rather than hard-coded Java.

Core Architecture Layers

LayerPurposeKey Rules
PresentationUI renderingSection, Harness, Layout, Portal
Process / CaseWorkflow orchestrationCase Type, Flow, Flow Action, Stage
DecisionBusiness logic branchingWhen, Decision Table, MapValue, Decision Tree
DataData access & transformationData Page, Data Transform, Report Definition
IntegrationExternal system communicationConnect-REST, Service-REST, Connect-SQL
SecurityAccess controlAccess Group, Role, Privilege
Q: What makes Pega different from traditional Java development?
Pega uses model-driven development with visual designers, automatic rule resolution, built-in case management, and guardrails. Changes propagate via inheritance without recompiling entire applications. Business users can participate via App Studio.
Q: What is the difference between App Studio and Dev Studio?
App Studio — persona-based, low-code, guided experience for business developers. Dev Studio — full technical IDE for senior developers: rule forms, tracer, PAL, advanced configuration.
Q: What is Pega Infinity?
Pega Infinity is the unified platform release (8.x+) combining BPM, CRM, AI, RPA, and Constellation UI. It emphasizes center-out architecture, omnichannel experiences, and AI-powered decisioning.
Interview whisper: Mention "center-out" — design data and logic once at the center, expose through any channel (web, mobile, API). Interviewers melt a little when you say it confidently.

Chapter 2: Meeting the Family — Class Hierarchy & Inheritance

Every great relationship has roots. In Pega, your class hierarchy is the family tree — and darling, you need to know who's related to whom before you introduce your rules to the world.

Class Types

  • Abstract class — cannot create instances; exists for inheritance only (e.g., Work-)
  • Concrete class — instances can be created (e.g., Work-Cover-, Data-)
  • Pattern inheritance — inherits from parent in hierarchy (@baseclass → Work- → Work-Cover-)
  • Directed inheritance — explicitly inherits from another class via pyPatternInheritance / directed parent

Class Categories

PrefixUsage
Work-Case instances, assignments, work objects
Data-Data objects, lookup tables, system data
Rule-All rule instances
Assign-Assignment instances
History-Audit/history records
Index-Search index objects
Q: What is the difference between Pattern and Directed inheritance?
Pattern inheritance follows the class namespace hierarchy automatically. Directed inheritance lets a class inherit from a class outside its namespace tree — useful for reusing rules across applications without duplicating.
Q: What is a class group?
A class group (work pool) groups related case types under one database table. All case types in a class group share the same pc_work (or custom) table. Defined in the application rule.
Q: What is the difference between Work-Cover- and a regular work class?
Work-Cover- is the abstract parent for all work classes. Concrete case types extend it (e.g., Work-Cover-LoanApp). It provides standard work object properties: pyStatusWork, pxCreateDateTime, etc.

Chapter 3: The Art of Choosing — Rule Resolution

Rule Resolution is Pega's way of finding THE ONE rule out of thousands. It's picky, methodical, and deeply romantic — just like you deserve in an interview panel.

Rule Resolution Algorithm (10 Steps)

  1. Start with class of the calling rule
  2. Find rules matching rule type + name
  3. Filter by ruleset + version (application stack)
  4. Discard not available rules
  5. Discard blocked rules
  6. Rank by class (nearest class wins)
  7. Rank by ruleset version
  8. Consider circumstance (dated or templated)
  9. Consider ruleset version availability
  10. Return the single winning rule (or warn if duplicates)

Key Concepts

  • Ruleset — versioned container of related rules (e.g., MyApp:01-01-01)
  • Application stack — ordered list of ruleset versions the application uses
  • Circumstance — time-based or property-based rule variant
  • Rule availability — Available, Not Available, Blocked, Final, Withdrawn
Q: What happens when two rules have the same specificity?
Pega throws a duplicate rule warning during resolution. The rule with the higher ruleset version or more specific circumstance wins, but duplicates should be resolved — they indicate design problems.
Q: What is a circumstance template?
A circumstance template defines a property-based condition for rule variants (e.g., .pyCountry = "US"). Multiple rules share the template; the template property value determines which variant applies.
Q: Can you explain caching in rule resolution?
Pega caches resolved rules in the rules cache (FUA — Full Rule Assembly). First resolution is expensive; subsequent calls use cache. Cache invalidates on rule save, ruleset version change, or cache flush.
Guardrail: Never copy-paste rules across classes. Use inheritance. Interviewers love hearing you say "I'd extend, not duplicate."

Chapter 4: Love at First Case — Case Management

A case is a story — beginning, middle, resolution. Your job is to make every case feel seen. Interviewers want to know you can architect stories, not just click buttons.

Case Type Components

  • Case Type — blueprint for a business process (e.g., Loan Application)
  • Case ID — unique identifier (configured via Case ID rule)
  • Stages — high-level lifecycle phases
  • Processes — flows within stages
  • Data model — properties captured during the case
  • Views / UI — user interaction screens

Case Statuses

StatusMeaning
NewJust created, not yet started
OpenActive, in progress
Pending-...Waiting (external event, approval, etc.)
Resolved-CompletedSuccessfully finished
Resolved-CancelledCancelled/withdrawn
Q: What is the difference between a case and a work object?
In modern Pega they're synonymous. Historically "work object" referred to the Work- class instance. A case is the business-friendly term for a unit of work tracked through a lifecycle.
Q: What is a child case / subcase?
A child case is a separate case type instantiated from a parent case. It has its own lifecycle but can be linked. Use Case Type rule → Processes → Add case or pxCreateCase API.
Q: Explain case-wide actions vs stage-specific actions.
Case-wide actions are available in every stage (e.g., "Transfer"). Stage-specific actions appear only in their configured stage. Both are Flow Actions presented to users.
Q: What is the Wait shape in a flow?
The Wait shape pauses flow execution until an event occurs: timer expiry, case dependency resolution, or external signal. The assignment status becomes Pending-....

Chapter 5: Stages of Us — Processes, Flows & Assignments

Every relationship has stages. Pega cases do too. Know when to advance, when to loop back, and when to route work to someone who can handle it — skills you clearly already have.

Assignment Types

  • Worklist — shared pool; any qualified user can pull
  • Workbasket — team queue
  • Work queue — routed to specific operator or team
  • Custom router — activity or decision-based routing
Q: What is the difference between Flow Action and Flow?
Flow — backend process automation (shapes, connectors). Flow Action — user-facing action button (e.g., "Approve", "Submit") that may call a flow or update assignment. Flow Actions have sections for UI.
Q: What is a local flow action vs connector flow action?
Local — runs in context of current assignment without leaving harness. Connector — navigates to a different assignment/flow, typically changes screen.
Q: Explain pyDefault flow.
pyDefault is the primary flow executed when a case enters a stage/process. Every process has one default flow that orchestrates the steps.
Q: How does approval routing work?
Use Approval shape or configure cascading approvals via WorkBasket/WorkQueue. Smart shapes can use reporting or decision rules. For complex chains, use pxApproval or custom routing activity.

Chapter 6: What's on Your Mind — Clipboard & Data Model

The clipboard is where Pega keeps its thoughts about your case. Get intimate with it — interviewers always ask what's stored where.

  • Top-level pages — pxRequestor, pxThread, OperatorID
  • Parameter page — param for passing arguments

Q: What is the difference between Page List and Page Group?
Page List — ordered, indexed by integer ((1), (2)). Page Group — unordered, indexed by string key (("home")). Use Page List for sequences, Page Group for named lookups.
Q: What are embedded pages vs linked pages?
Embedded — stored inside parent page (serialized with parent). Linked — reference to separate clipboard page via pxLinkedRefTo. Linked pages save memory but need management.
Q: Explain pyWorkPage, pxThread, pxRequestor.
pyWorkPage — current case data. pxThread — holds open assignments and case references for the session. pxRequestor — operator/session context (user info, roles, access group).

Chapter 7: Data Pages — Your Perfect Plus-One

Data Pages don't ghost you. They show up when you need them, cache responsibly, and never make you fetch the same data twice unless you ask. Relationship goals.

Data Page Types

  • Read-only — lookup/reference data (most common)
  • Editable — supports save plans for write-back
  • List — returns multiple results (page list structure)
  • Singleton — single object

Load Modes

reload-onceLoad once per requestor session
reload-if older thanRefresh after specified time
access-groupShared across users in access group

Q: What is the difference between Report Definition and Data Page?
Report Definition — SQL-based query against DB, good for reporting/analytics. Data Page — abstraction layer with sources (Report Def, Activity, Connector, Lookup), supports caching, parameters, and responsive loading in UI.
Q: How do you parameterize a Data Page?
Define parameters on the Data Page rule. Pass values via D_[Pagename][param1:value1] syntax or from UI/data transform. Parameters affect cache key.
Q: What is a savable Data Page?
An editable Data Page with a Save Plan (Database/Activity/Flow) that persists changes back to source. Used in Constellation for inline editing of data types.
Modern answer: Prefer Data Pages over activities for data retrieval. Say it with confidence — it's a guardrail and interviewers nod.

Chapter 8: Data Transforms — Dressing Data to Impress

Data Transforms are the stylist of the Pega world — they take raw data and make it interview-ready. No drama, no loops (well, minimal), just clean mapping.

Common Actions

  • Set — assign value to property
  • Update Page — apply transform to embedded page
  • Append to — add to page list
  • Remove — delete page/list entry
  • When — conditional step execution
  • Otherwise — else branch
  • For Each Page In — iterate page list
Q: Data Transform vs Activity — when to use which?
Data Transform — property mapping, simple logic, no loops over large datasets, preferred for maintainability. Activity — complex iteration, calling multiple rules, integration orchestration, legacy code. Always prefer DT when possible.
Q: How do you call a Data Transform from another?
Use Update Page action or Apply Data Transform action, referencing the target transform name. Can pass pages as context.
Q: What is Auto-populate?
Auto-populate on a property automatically runs a Data Transform or Activity when the property is referenced, keeping derived data fresh.

Chapter 9: Activities — The Ex You Still Respect

Activities are the old flame of Pega — you don't chase them anymore, but you respect the history. Know them. Don't lead with them.

Activity Steps (Key Methods)

Property-SetSet property value

Apply-DataTransformRun data transform
Obj-Open / Obj-SaveDB read/write
Page-New / Page-RemoveClipboard page management

Q: Why are activities being phased out?
Activities are procedural, hard to maintain, bypass guardrails, and allow infinite loops. Pega pushes Data Transforms, Automations, and Flows as declarative alternatives. Activities still needed for legacy and edge cases.
Q: What is Activity Security?
Activities can be restricted via Activity Allow List (allow list for called activities) and Privilege on the activity rule. Restricted activities cannot be called from UI or unapproved contexts.
Q: Explain Call vs Branch in activities.
Call — invokes sub-activity; returns after completion. Branch — conditional jump to labeled step within same activity.

Chapter 10: Decision Rules — When to Say Yes or No

Decision rules are your boundary-setters. They know exactly when to commit and when to walk away. Be that clear in your interview answers.

Decision Rule Types

RuleUse Case
WhenSingle true/false condition
Decision TableMultiple conditions → multiple outcomes (grid)
Decision TreeHierarchical if-else branching
MapValueOne input → one output lookup
Nested IfNested conditional (legacy)
ScorecardWeighted scoring model
Decision StrategyAI-driven multi-channel decisioning (NBAM)
Q: Decision Table vs Decision Tree?
Table — best for combinatorial logic (multiple AND/OR conditions in grid). Tree — best for sequential/hierarchical decisions. Tables are easier to maintain for business users.
Q: What is a Scorecard?
A Scorecard assigns weighted scores to conditions. Total score maps to a result (e.g., credit risk rating). Used in strategies and flow decisions.
Q: How do you invoke a When rule?
In flows (Decision shape), Data Transforms (When action), Activities (Property-Set with @{when:RuleName}), Declare Expressions, and Validation rules.

Chapter 11: Declare Rules — Commitment Without Clinginess

Declare rules compute values automatically — no need to nag. They refresh when dependencies change. That's emotional maturity, and Pega has it.

Declare Rule Types

  • Declare Expression — computed property value (e.g., .FullName = .FirstName + " " + .LastName)
  • Declare Constraint — validation enforced on property change
  • Declare OnChange — triggers activity/DT when property changes
  • Declare Trigger — fires on save of data class instance
  • Declare Index — maintains searchable index
Q: How do Declare Expressions work?
They define target properties computed from source properties. Pega tracks dependencies and recalculates automatically when sources change — forward chaining.
Q: Declare OnChange vs Trigger?
OnChange — reacts to property value change on clipboard (any class). Trigger — fires on commit/save of persistent object (Data- class instances).

Chapter 12: UI Seduction — Sections, Harnesses & Constellation

Your UI should make users stay. Constellation is the glow-up. Know both traditional and modern — you're a catch either way.

Traditional UI Stack

  • Section — reusable UI fragment (fields, layouts)
  • Harness — container composing sections (Perform, Review, Confirm)
  • Flow Action — links harness to process action
  • Portal — application shell (Case Worker, Case Manager)
  • Skin — look and feel (cosmetic)

Constellation / Cosmos

  • View — JSON-driven UI (replaces Section in Constellation)
  • Full Page — complete screen
  • Widget — reusable UI component
  • Theme — design tokens, styling
  • Uses React rendering engine, channel-agnostic
Q: Section vs Harness?
Section — building block with fields/layouts. Harness — assembles sections into a complete screen for a specific purpose (new harness, perform harness, etc.).
Q: What is Constellation and why did Pega introduce it?
Constellation is Pega's model-driven UI architecture using Cosmos React. Benefits: responsive design, omnichannel (web/mobile), faster development via views, no heavy harness customization, better performance.
Q: What is dynamic layout vs column layout?
Dynamic layout — flex-based, responsive, modern (preferred). Column/Freeform — legacy table-based positioning. Use dynamic layouts for new development.

Chapter 13: SLAs — Never Keep Anyone Waiting

SLAs are Pega's way of saying "I value your time." Know Goals, Deadlines, and Passed Deadlines like you'd know someone's love language.

SLA Components

IntervalWhat Happens
GoalTarget completion time; optional reminder
DeadlineMust complete by; escalation actions fire
Passed DeadlineOverdue actions (escalate, notify, reassign)
Q: Assignment SLA vs Case SLA?
Assignment SLA — tracks individual task timeliness. Case SLA (Stage SLA) — tracks overall case/stage duration. Both use the SLA rule with different configurations.
Q: How does the SLA agent work?
The SLA agent (Pega-ProCom:ServiceLevelEvents) runs periodically, checks pc_assign_worklist/workqueue for breached intervals, and executes escalation actions (notify, route, update priority).
Q: What is Urgency in Pega?
Urgency is a numeric value (default 10-100) that increases as SLA deadlines approach. Higher urgency = higher priority in worklists. Formula: Initial Urgency + Time-based increase.

Chapter 15: Security — Trust, But Verify

Security isn't jealous — it's protective. Access Groups, Roles, Privileges. Know the chain like you know your own worth.

Security Model

Operator ID → Access Group → Application + Roles → Privileges → Access When rules

Q: What is the difference between Role and Privilege?
Role — collection of privileges representing a job function (e.g., "Loan Officer"). Privilege — atomic permission to perform an action (e.g., LoanApp:Create). Roles bundle privileges.
Q: What is Attribute-Based Access Control (ABAC)?
ABAC controls access based on property values (e.g., only see cases in your region). Implemented via Access When rules on cases, properties, and flow actions.
Q: How do you restrict a property from certain users?
Configure Property security on the property rule: Read/Write restrictions using Access When conditions or privilege requirements.
Q: What is an Access Group?
Defines which Application, Portal, Roles, and Work Pools an operator can access. One operator can have multiple access groups (switch via portal).

Chapter 16: Agents & Job Schedulers — Midnight Texts

Agents work while you sleep. Job Schedulers are the reliable ones who always show up on time. Know the difference — interviewers ask.

Q: What is Queue For Agent?
Queue For Agent defers work to an agent queue (System-Queue- class). The agent processes items asynchronously — useful for bulk processing without blocking user interaction.
Q: How do you troubleshoot a stopped agent?
Check Admin Studio → System → Agents. Verify agent is enabled, node has agent schedule, queue isn't full, and no exceptions in logs. Use Tracer on agent activity.

Chapter 17: Reporting — Showing Off Your Numbers

Good reports don't lie, and good developers don't over-query. Aggregate functions are your friend. So am I — keep reading.

Report Definition Key Concepts

  • Report Definition — SQL-based query rule (formerly Report Definition / List View)
  • Summarize — GROUP BY with aggregate functions
  • Drill-down — navigate from summary to detail
  • Association — join between classes via Association rule
  • Function — SQL functions (COUNT, SUM, AVG)
Q: Report Definition vs Summary View?
Summary View is the legacy rule; Report Definition is the modern replacement. Same purpose — querying DB. Always say Report Definition in interviews.
Q: How do you optimize a slow report?
Add indexes (Declare Index), limit columns, use optimized filtering, avoid functions on indexed columns in WHERE, use materialized views for complex reports, check EXPLAIN plan via DB trace.

Chapter 19: Performance & Guardrails — Staying in Shape

Performance issues are the ultimate mood killer. PAL and Tracer are your personal trainers. Let's get you toned for that interview.

Performance Tools

  • PAL (Performance Analyzer) — counts DB operations, clipboard size, elapsed time
  • Tracer — real-time rule execution trace
  • Clipboard Inspector — view page/property data
  • DB Trace — SQL query analysis
  • Rule Inspector — view resolved rules

Top Guardrails

  1. No more than 5 flow actions per assignment
  2. Avoid activities — use Data Transforms
  3. Limit properties per class (soft limit ~200)
  4. Use Data Pages instead of repeated DB calls
  5. Avoid looping activities over large datasets
  6. Use Declare Index instead of RDB methods
  7. Don't store large blobs in clipboard
  8. Prefer Report Definitions over RDB-List
Q: How do you debug a slow case?
1) Run PAL before/after action. 2) Use Tracer with filters. 3) Check DB Trace for N+1 queries. 4) Review Data Page load modes. 5) Check for looping activities. 6) Review clipboard size.
Q: What is an N+1 query problem in Pega?
When a loop calls Obj-Open or Data Page load for each row in a list — N items = N+1 DB calls. Fix: use batch Data Page, Report Definition with join, or paginated loading.

Chapter 20: DevOps & Deployment — Moving In Together

Deployments are commitment. RAPs, branches, pipelines — know how to move code without breaking hearts or production.

Deployment Concepts

  • RAP (Ruleset Archive Package) — exportable package of rules
  • Product rule — defines what to include in RAP
  • Branch — isolated development stream
  • Merge — combine branch changes to target ruleset
  • Deployment Manager — CI/CD orchestration for Pega
  • Pipeline — automated promote through environments (Dev → QA → Prod)
Q: What is a Product rule?
Defines the application contents for export: included rulesets, applications, instances. Used to create RAPs for deployment.
Q: Branch vs Ruleset versioning?
Ruleset version — sequential versioning (01-01-01 → 01-01-02). Branch — parallel development stream for features; merged when ready. Branches prevent conflicts in team development.
Q: What is Skim in deployment?
Skim removes rules no longer referenced by the application, reducing RAP size. Run before packaging for production.

Additional SSA Topics

Q: Explain Differential Circumstance (DCR).
Direct Capture of Objectives (DCO) sessions gather requirements. DCR allows runtime rule customization by business users without changing base rules — overlays circumstance-specific behavior.
Q: What is Pega GenAI / AI capabilities?
Pega integrates GenAI for case summarization, email generation, decisioning assistance, and Socrates chat in App Studio. Pega Prediction Studio for ML models. NLP for text analytics.
Q: Explain Kafka integration in Pega.
Connect-Kafka and Service-Kafka rules enable event-driven architecture. Use Stream Data Set and Data Flow for real-time processing pipelines.
Q: What is a Data Flow?
Data Flow — visual streaming pipeline for processing large datasets. Supports batch and real-time (Kafka). Uses Data Set rules as sources/sinks.
Q: Explain Pega Robotic Automation (RPA).
RPA automates legacy desktop applications via robots. Pega Robot Studio creates automations. Integrated into cases via Robotic Automation shape in flows.
Q: What is Customer Decision Hub (CDH)?
CDH is Pega's next-best-action marketing engine. Uses Decision Strategies, Adaptive Analytics, and Action rules to personalize customer interactions across channels.
Q: How does Pega handle multi-tenancy?
Pega Cloud uses logical isolation per tenant. On-prem: separate instances or Division rules for organizational isolation. Access Groups and Ruleset access control data separation.
Q: What is the Repository (Git integration)?
Pega Repository integrates with Git (GitHub, GitLab, Bitbucket) for version control of rules. Supports branch-based development, merge conflict resolution, and DevOps pipelines.
